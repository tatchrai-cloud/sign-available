# ระบบตรวจสอบวันลงนามเอกสาร (Sign Date Available)

เว็บแอป **ไฟล์ HTML ไฟล์เดียว** สำหรับบันทึกวันที่บุคลากร/ผู้บังคับบัญชา **ลงนามไม่ได้** (เดินทางไปราชการ ลา อบรมนอกพื้นที่)
เก็บข้อมูลใน **Firebase Realtime Database** — ไม่ต้องล็อกอิน ไม่มีรหัสผ่าน — เปิดผ่าน **GitHub Pages** ได้ทั้งคอมและมือถือ
และให้ Claude ดึงข้อมูลไปตรวจวันที่ในเอกสารเบิก/จัดซื้อจัดจ้างได้

## ไฟล์ในโฟลเดอร์

| ไฟล์ | หน้าที่ | ขึ้น GitHub? |
|---|---|---|
| `index.html` | หน้าเว็บทั้งระบบ (ไม่มีรหัสลับในไฟล์) | ✅ |
| `database.rules.json` | กฎความปลอดภัยของฐานข้อมูล | ✅ |
| `README.md` | คู่มือนี้ | ✅ |
| `.gitignore` | กันไฟล์ลับไม่ให้ขึ้น GitHub | ✅ |
| `ลิงก์แชร์-ห้ามเผยแพร่.txt` | ลิงก์แชร์ของหน่วยงาน | ❌ **ห้าม** |
| `claude-config.json` | ค่าให้ Claude อ่านฐานข้อมูล (มีรหัส) | ❌ **ห้าม** |
| `tools/`, `CLAUDE.md` | เครื่องมือ/คำแนะนำสำหรับ Claude | ไม่จำเป็น |
| `legacy-google-sheet/` | โค้ดระบบเดิมแบบ Google Sheet (เก็บไว้อ้างอิง) | ❌ |

## หลักการนับวันลงนาม

- **เสาร์–อาทิตย์** และ **วันหยุดนักขัตฤกษ์** = ลงนามไม่ได้ทุกคน (ระบบคิดให้อัตโนมัติ)
- **วันที่ลงนามไม่ได้รายบุคคล** = ผู้ใช้กำหนดเองในหน้าเว็บ ระบบแค่ "แนะนำ" ค่าเริ่มต้นให้
  - เดินทางไปราชการ / อบรมนอกพื้นที่ เช่น 1–3 ต.ค. 69 → วันที่ 1 และ 3 (วันเดินทางไป-กลับ) **ลงนามได้**, วันที่ 2 **ลงนามไม่ได้**
  - ลา / ภารกิจอื่น → ลงนามไม่ได้ทุกวัน
  - แตะที่วันเพื่อสลับ ลงนามได้ ⇄ ลงนามไม่ได้ ได้ตามจริง

## ขั้นที่ 1 · ตั้งกฎความปลอดภัยของฐานข้อมูล (สำคัญที่สุด — ทำก่อน)

ตอนนี้ Realtime Database อยู่ใน **test mode** = ใครก็อ่าน/เขียน/ลบได้ทั้งฐานข้อมูล ต้องเปลี่ยนก่อนใช้งานจริง

1. เข้า <https://console.firebase.google.com/project/sign-available/database> (ล็อกอินบัญชี Google เจ้าของโปรเจกต์)
2. แท็บ **Rules** › ลบข้อความเดิมทั้งหมด › วางเนื้อหาไฟล์ `database.rules.json` ทั้งไฟล์ › **Publish**

## ขั้นที่ 2 · เอาขึ้น GitHub Pages (ผ่านหน้าเว็บ ไม่ต้องติดตั้งโปรแกรม)

1. เข้า <https://github.com> แล้วล็อกอิน (ยังไม่มีบัญชี › **Sign up** สมัครฟรี)
2. มุมขวาบน กด **＋ › New repository**
   - Repository name: เช่น `sign-date` (ภาษาอังกฤษ ไม่มีเว้นวรรค)
   - เลือก **Public** (GitHub Pages ฟรีต้องเป็น Public — ไม่เป็นไร เพราะในไฟล์ไม่มีรหัสลับ)
   - กด **Create repository**
3. ในหน้า repo ใหม่ กดลิงก์ **uploading an existing file**
   - ลากไฟล์ **4 ไฟล์นี้เท่านั้น** ลงไป: `index.html`, `database.rules.json`, `README.md`, `.gitignore`
     (ถ้า Windows ซ่อน `.gitignore` ไม่ต้องอัปโหลดก็ได้)
   - ⚠️ **ห้าม** ลาก `claude-config.json` หรือ `ลิงก์แชร์-ห้ามเผยแพร่.txt` หรือทั้งโฟลเดอร์
   - เลื่อนลงล่าง กด **Commit changes**
4. ไปที่แท็บ **Settings › Pages** (เมนูซ้าย)
   - Source: **Deploy from a branch** · Branch: **main** · โฟลเดอร์: **/ (root)** › **Save**
5. รอ 1–2 นาที แล้วรีเฟรชหน้า Settings › Pages จะเห็น **Your site is live at** `https://<ชื่อผู้ใช้>.github.io/sign-date/`

> **แก้ไขไฟล์ภายหลัง:** เข้า repo › กดไฟล์ `index.html` › ไอคอนดินสอ (Edit) หรือ **Add file › Upload files** อัปโหลดไฟล์ใหม่ทับชื่อเดิม › Commit changes — เว็บอัปเดตเองใน 1–2 นาที

## ขั้นที่ 3 · แชร์ลิงก์ให้ทีม

1. เปิดไฟล์ `ลิงก์แชร์-ห้ามเผยแพร่.txt` ในเครื่องนี้ › นำ URL จากขั้นที่ 2 มาต่อท้ายด้วย `#k=…` ตามที่เขียนไว้
2. เปิดลิงก์นั้นเองก่อน 1 ครั้ง (ระบบจะใส่วันหยุดตั้งต้นให้) › เพิ่มบุคลากร
3. ส่งลิงก์ให้เฉพาะคนในหน่วยงาน (LINE ส่วนตัว/อีเมลภายใน) — เปิดครั้งแรกครั้งเดียว ระบบจำไว้ในเบราว์เซอร์นั้น
   ครั้งต่อไปเปิด `https://<ชื่อผู้ใช้>.github.io/sign-date/` เฉย ๆ ได้เลย (มือถือแนะนำ "เพิ่มลงในหน้าจอโฮม")
4. ภายหลังดู/คัดลอกลิงก์ได้จาก **ปุ่มสถานะมุมขวาบน › ลิงก์แชร์**

คนที่เปิดเว็บ **โดยไม่มีลิงก์แชร์** จะเห็นเฉพาะโหมดทดลอง (ข้อมูลตัวอย่าง) ไม่เห็นข้อมูลจริง

## ความปลอดภัย — ทำอะไรไว้บ้าง

| มาตรการ | ป้องกันอะไร |
|---|---|
| ไฟล์บน GitHub **ไม่มีรหัสลับ** | ค่า `apiKey` ของ Firebase เป็นค่าสาธารณะตามที่ Google ออกแบบ ไม่ใช่รหัสผ่าน — การเข้าถึงข้อมูลควบคุมด้วย rules |
| ข้อมูลอยู่ใต้รหัสสุ่ม 32 ตัว (`spaces/<รหัส>`) และ rules **ห้ามดูรายการ spaces** | เดารหัสไม่ได้ (ความเป็นไปได้ ~10⁵⁶ แบบ) — ไม่มีลิงก์ = เข้าไม่ได้ |
| รหัสส่งผ่าน `#k=` และถูกลบจากแถบที่อยู่ทันที | ส่วนหลัง `#` ไม่ถูกส่งไปเซิร์ฟเวอร์ ไม่ค้างใน log/ประวัติ/ภาพหน้าจอ |
| rules ตรวจ **ทุกฟิลด์** (ชนิด รูปแบบวันที่ ความยาวสูงสุด ห้ามฟิลด์แปลกปลอม รายการต้องอ้างบุคลากรที่มีอยู่จริง) | กันการยัดข้อมูลขยะ/ข้อมูลขนาดใหญ่/โครงสร้างแปลก ๆ |
| rules **ห้ามลบพื้นที่ข้อมูลทั้งก้อน** | กันการล้างข้อมูลทั้งหมดในคำสั่งเดียว |
| ทุกข้อความแสดงผลผ่านการ escape HTML + **Content-Security-Policy** | กัน XSS / script แปลกปลอม — หน้าเว็บโหลดได้เฉพาะ Firebase, Google Fonts, reCAPTCHA |
| ปุ่ม **สำรอง/กู้คืนข้อมูล** (.json) | ถ้ามีคนแก้/ลบข้อมูลผิด กู้คืนได้ — แนะนำสำรองเดือนละครั้ง |
| (ไม่บังคับ) **App Check + reCAPTCHA v3** | ฐานข้อมูลรับคำขอเฉพาะจากหน้าเว็บของคุณบนโดเมน github.io — กันสคริปต์ยิงตรง |

**ข้อจำกัดที่ต้องรู้:** เพราะไม่มีล็อกอิน **ใครมีลิงก์แชร์ = แก้ไขข้อมูลได้** ระบบแยกไม่ได้ว่าใครเป็นคนแก้
ดังนั้นแชร์ลิงก์เฉพาะคนในหน่วยงาน และถ้าลิงก์หลุด ให้เปลี่ยนรหัสตามวิธีใน `ลิงก์แชร์-ห้ามเผยแพร่.txt`

### (แนะนำ) เปิด App Check — กันสคริปต์ภายนอก
1. <https://www.google.com/recaptcha/admin/create> › reCAPTCHA **v3** › Domains: `<ชื่อผู้ใช้>.github.io` › Submit › ได้ **Site key** และ **Secret key**
2. Firebase console › **Build › App Check** › Apps › แอปเว็บ › **reCAPTCHA** › วาง **Secret key** › Save
3. แก้ `index.html` บน GitHub: ใส่ Site key ที่ `RECAPTCHA_SITE_KEY: '…'` › Commit › เปิดเว็บทดสอบว่ายังใช้งานได้
4. ให้ Claude ยังอ่านได้: App Check › Apps › เมนู ⋮ › **Manage debug tokens** › Add debug token › คัดลอก › ใส่ใน `claude-config.json` ช่อง `appCheck.debugToken`
5. App Check › APIs › **Realtime Database** › **Enforce**
   (ถ้าเปิด enforce แล้ว การเปิดไฟล์ด้วยการดับเบิลคลิกในเครื่องจะใช้ข้อมูลจริงไม่ได้ ต้องเปิดผ่าน github.io)

## โครงสร้างข้อมูล

ทุกอย่างอยู่ใต้ `spaces/<รหัส>/`

| โหนด | key | ฟิลด์ |
|---|---|---|
| `staff` | อัตโนมัติ | name, position, role (พนักงาน/ผู้บังคับบัญชา), department, active, order, createdAt |
| `events` | อัตโนมัติ | staffId, staffName, type, title, startDate, endDate, blockedDates[], note, createdAt, updatedAt |
| `holidays` | `yyyy-mm-dd` | date, name — แก้ได้ในหน้าเว็บ (แท็บวันหยุด) |

วันที่เก็บเป็นข้อความ `yyyy-mm-dd` (ค.ศ.) ส่วนหน้าเว็บแสดงเป็น พ.ศ.

## ให้ Claude ตรวจวันลงนาม

`claude-config.json` ในเครื่องนี้ตั้งค่าไว้แล้ว (databaseURL + dataKey) — Claude ใช้ `tools/signdate.ps1` (Windows) หรือ `tools/signdate.py` (Cowork/Linux/Mac) ตามวิธีใน `CLAUDE.md`
ตัวอย่างการสั่งในแชต: *"เช็คว่าวันที่ 2/10/2569 ผอ. ลงนามได้ไหม"* หรือ *"ตรวจวันที่ในเอกสารชุดนี้ว่าผู้ลงนามอยู่ปฏิบัติงานไหม"*

| คำสั่ง | ตัวเลือก | ผลลัพธ์ |
|---|---|---|
| `check` | `date` (หลายวันคั่น comma), `names` | แต่ละวัน: ทุกคนลงนามได้ไหม, เหตุผลรายคน, วันใกล้เคียงที่ลงนามได้ |
| `range` | `from`, `to`, `names` | รายวันในช่วง พร้อมรายชื่อที่ลงนามไม่ได้ |
| `suggest` | `date`, `names`, `n` | วันที่ใกล้ที่สุดก่อน/หลังที่ทุกคนลงนามได้ |
| `events` | `names`, `from`, `to` | รายการเดินทาง/ลา |
| `staff` / `holidays` / `all` / `help` | – | ข้อมูลดิบ |

## หมายเหตุ

- วันหยุดตั้งต้นมีปี 2569 ครบ และปี 2570 เฉพาะวันที่ตายตัว — วันหยุดตามจันทรคติปี 2570 และวันหยุดพิเศษตามมติ ครม. เพิ่มเองในแท็บ **วันหยุด**
- บุคลากรที่ย้าย/เกษียณ ให้ยกเลิกติ๊ก "ใช้งานอยู่" แทนการลบ เพื่อเก็บประวัติไว้ตรวจเอกสารย้อนหลัง
- Firebase แผนฟรี (Spark) และ GitHub Pages ฟรี เพียงพอสำหรับการใช้งานระดับสำนักงาน
- ต้องต่ออินเทอร์เน็ตขณะใช้งาน
